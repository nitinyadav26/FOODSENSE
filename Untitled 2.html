HIGH-LEVEL SYSTEM CONTEXT

========================


Hardware:

- Smart food scale uses:

  - Load cell + HX711 for weight.

  - STM32H7 as main MCU (for future DCMI camera + TFT screen).

  - ESP32 is used as communication module (BLE and possibly Wi-Fi later).

- For this FIRST VERSION of the app:

  - The iOS phone camera is used for capturing food images.

  - ESP32 exposes a BLE service that sends the current weight in grams to the phone.

  - The iOS app reads that weight, captures a food image from the phone camera, and sends both to the backend.


BLE Protocol (for this MVP):

- ESP32 exposes a BLE service with (example UUIDs, you can use these in the code):

  - Service UUID:       "0000FFF0-0000-1000-8000-00805F9B34FB"

  - Weight characteristic UUID: "0000FFF1-0000-1000-8000-00805F9B34FB"

- The weight characteristic:

  - Notifies frequently (e.g., every 200 ms) with current weight in grams.

  - Value format is a 4-byte little-endian signed Int32 representing grams (e.g., 185 = 185 grams).

- ESP32 may later have a “command” characteristic for tare/calibration, but for now:

  - You may define a second characteristic (e.g. "0000FFF2-0000-1000-8000-00805F9B34FB") if you want to show how to send commands.

  - But the critical one is the weight notify characteristic.


Backend:

- There is a backend server (you can assume a base URL constant, e.g.:

  - BASE_URL = "https://api.foodsense.example.com"

- The main endpoint for now is:

  - POST /api/analyze_meal

- The app sends:

  - multipart/form-data with:

    - "weight_grams": integer (total grams from scale at the moment of capture)

    - "image": JPEG binary of the food photo captured by the phone camera

    - (Optionally) "meal_type", "user_notes" as simple text fields.

- The backend calls Gemini with a long system prompt and returns a JSON response with nutritional info.
